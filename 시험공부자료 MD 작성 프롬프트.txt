자료 범위:
- 문제 내용과 `출처:`는 반드시 마지막 줄에 붙여넣은 시험범위 자료 경로 안의 파일만 사용한다.
- 경로 밖의 주변 폴더, 이전 시험 레퍼런스, 다른 시험범위 자료는 출제 경향과 문제화 방식 참고까지만 허용한다. 바깥 자료의 내용을 현재 문제의 정답 근거로 쓰거나 `출처:`에 적지 않는다.
- 사용자가 준 경로가 `...\중간고사 정리자료`라면 그 폴더 안의 파일만 문제 내용과 출처로 쓴다. 형제 폴더를 임의로 출처에 넣지 않는다.

작업 순서:
- 바로 문제를 쓰지 않는다. 먼저 전체 자료를 탑다운으로 파악하고 Goal 단계로 나눈 뒤 단계별로 문제를 만든다.
- 1단계는 `전체 구조 파악`: 폴더 구조, 파일명, 기출/수업자료/정리자료/보조자료 위치, 시험범위의 큰 단원 구성을 정리한다.
- 2단계는 `출제 우선순위 지도 작성`: 기출 축, 수업자료 강조 축, 레퍼런스 축을 나누어 어떤 내용을 먼저 문제화할지 정한다.
- 자료가 많으면 단원, 주차, 강의 회차, 교재 챕터, 파일명 번호, 기출 범위처럼 자연스럽게 끊기는 지점을 찾아 더 작게 나눈다.
- 각 단계는 `자료 확인 -> 중요 포인트 선별 -> 필요한 이미지 캡처/재구성 -> 문제 작성 -> 출처 확인` 순서로 진행한다.
- 마지막에만 전체 Markdown을 통합하고 중복, 누락, 기출 우선 배치, 출처, 이미지 누락을 점검한다.

0순위 기출:
- 기출 파일, 기출 풀이, 족보, 예상문제, 과거 시험 문제처럼 시험 문제 형태의 자료가 있으면 가장 먼저 분석한다.
- 기출문제는 최대한 원문 그대로 복원한다. 문제 표현, 보기, 순서, O/X 문장, 표기 방식, 함정 포인트를 임의로 리메이크하지 않는다.
- 기출 객관식, O/X, 빈칸, 연결형, 표 문제를 단답형 문제로 바꾸지 않는다. 원문이 단답형이 아닌데 단답형으로 바꾸면 실패다.
- 기출 원문이 흐리거나 누락된 경우에도 `확인 필요`로 방치하지 않는다. 현재 시험범위 자료로 복원하거나, 복원 불가한 부분은 문제를 성립하게 다시 구성한다.

1순위 수업자료 강조:
- PPT/PDF/슬라이드는 텍스트 추출만 믿지 말고 페이지 이미지를 직접 보면서 판단한다.
- 빨간색, 형광색, 굵게, 밑줄, 박스, 별표, 화살표, 도식 중심부, 비교표, 색상 구분, 반복 등장, 큰 글씨, 교수 강조 문구를 우선 문제화한다.
- 단순 디자인 테마 색과 실제 강조 색을 구분한다.

이미지/표:
- 그림, 도식, 구조식처럼 문제를 풀기 위해 봐야 하는 자료만 문제 본문에 넣는다.
- 표, 비교표, 계산표는 답이 보이지 않게 문제 본문용 이미지를 직접 재구성한다. 빨간 숫자, 정답 표시, 채점 흔적, 답 암시 색상은 제거한다.
- 표, 비교표, 계산표, 원본 근거 화면은 답안 아래 참고 이미지로도 넣는다.
- 계산 문제는 원본 표와 수치 조건을 문제 본문에 제공한다.

Markdown 형식:
```md
# 문제

실제 문제 텍스트를 바로 적는다.
![필요한 이미지](assets/과목명/img-001.png)

- 보기 A
- 보기 B

답: 보기 A
출처: 파일명.pdf p.12
![출처 페이지](assets/과목명/source-001.png)
```

작성 규칙:
- `# 문제`는 구분선일 뿐 제목이 아니다. 답을 유추하게 만드는 문제 제목을 만들지 않는다.
- 보기 앞 원문 번호는 제거한다. 예: `① 칼슘...`, `5. 인...`처럼 쓰지 말고 `- 칼슘...`, `- 인...`처럼 보기 내용만 적는다.
- 답은 번호가 아니라 보기 내용으로 적는다. `답: 5`, `답: ⑤`, `답: 5. 보기`처럼 쓰지 않는다.
- 복원 안 된 보기, `C는 ~`, `A는 ?`, `확인 필요 보기`처럼 미완성 보기를 그대로 두지 않는다.
- 누락된 선지는 자료를 참고해 맞거나 틀린 완성 선지로 재구성하고, 그에 맞춰 정답도 확정한다.
- `① ㄱ,ㄴ`, `② ㄱ,ㄷ` 같은 복합형 조합 보기는 만들지 않는다. `옳은 것을 모두 고르시오`로 묻고 답은 `ㄱ, ㄹ, ㅁ`처럼 진술 기호만 적는다.
- 모든 답안에는 `출처:` 줄과 출처 페이지/슬라이드 원본 이미지를 답안 맨 아래에 둔다.
- 답안은 줄글로 길게 쓰지 않는다. 자료에 있는 사실만 짧게 적고, `암기포인트:`, `핵심:`, `요약:` 같은 임의 라벨은 붙이지 않는다.
- 핵심 단어/숫자/조건/예외는 `**빨간 강조**`, 반드시 외울 묶음은 `==하이라이트==`로 표시한다.
- 단어, 짧은 구, 기호, 식, O/X, 키워드 나열처럼 문장이 아닌 답에는 마침표를 붙이지 않는다.

최종 점검:
- 최종 Markdown과 assets가 지정 위치에 실제로 있는가?
- 기출이 있는데 기출 분석 없이 만든 문제가 없는가?
- 각 문제 답안에 `출처:`가 있는가?
- 그림/표/도식/색상 강조가 핵심인 문제에 실제 이미지가 들어갔는가?
- 문제 제목, 보기 순서, 단순 번호 순서만 보고 답이 유추되지 않는가?
