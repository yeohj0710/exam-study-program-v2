너는 Exam Study Program에서 바로 열 수 있는 시험공부용 Markdown 문제 데이터를 만든다.

사용자는 마지막 줄에 시험범위 자료 경로만 붙여넣는다. 과목명, 시험명, 저장할 Markdown 위치, 레퍼런스 위치, 문제 수는 스스로 판단한다. 문제 수를 미리 정하지 말고 실제 시험에 나올 가능성이 높은 것만 만든다.

작업 시작 전에 반드시 `C:\dev\exam-study-program-v2\프로그램 구성 파일\prompts\시험공부자료 MD 작성 상세 프롬프트.txt`를 읽고 따른다. 단, 사용자에게 추가 입력 항목을 요구하지 말고 마지막 줄의 시험범위 자료 경로만 입력으로 본다.

자료 범위:
- 문제 내용과 `출처:`는 반드시 마지막 줄에 붙여넣은 시험범위 자료 경로 안의 파일만 사용한다.
- 경로 밖의 주변 폴더, 이전 시험 레퍼런스, 다른 시험범위 자료는 출제 경향과 문제화 방식 참고까지만 허용한다. 바깥 자료의 내용을 현재 문제의 정답 근거로 쓰거나 `출처:`에 적지 않는다.
- 사용자가 준 경로가 `...\중간고사 정리자료`라면 그 폴더 안의 파일만 문제 내용과 출처로 쓴다. 형제 폴더를 임의로 출처에 넣지 않는다.

저장:
- 최종 Markdown은 `C:\dev\exam-study-program-v2\문제 데이터` 바로 아래에 저장한다.
- 파일명은 과목명과 시험명을 알아볼 수 있게 정한다. 예: `예방약학_기말고사_문제.md`.
- 이미지는 `C:\dev\exam-study-program-v2\문제 데이터\assets\<Markdown 파일명>\...` 아래에 저장하고, Markdown에는 `assets/<Markdown 파일명>/...` 상대 경로만 넣는다.

작업 순서:
- 바로 문제를 쓰지 않는다. 먼저 전체 자료를 탑다운으로 파악하고 작업 단계를 나눈 뒤 단계별로 문제를 만든다.
- 1단계는 `전체 구조 파악`: 폴더 구조, 파일명, 기출/수업자료/정리자료/보조자료 위치, 시험범위의 큰 단원 구성을 정리한다.
- 2단계는 `출제 우선순위 지도 작성`: 기출 축, 수업자료 강조 축, 레퍼런스 축을 나누어 어떤 내용을 먼저 문제화할지 정한다.
- 자료가 많으면 Goal 작업으로 보고 단원, 주차, 강의 회차, 교재 챕터, 파일명 번호, 기출 범위처럼 자연스럽게 끊기는 지점을 찾아 단계별로 나눈다.
- 각 단계는 `자료 확인 → 중요 포인트 선별 → 필요한 이미지 캡처/재구성 → 문제 작성 → 출처 확인` 순서로 진행한다.
- 마지막에만 전체 Markdown을 통합하고 중복, 누락, 기출 우선 배치, 출처, 이미지 누락을 점검한다.

0순위 기출:
- 기출 파일, 기출 풀이, 족보, 예상문제, 과거 시험 문제처럼 시험 문제 형태의 자료가 있으면 가장 먼저 분석한다.
- 기출문제는 최대한 원문 그대로 복원한다. 문제 표현, 보기, 순서, O/X 문장, 표기 방식, 함정 포인트를 임의로 리메이크하지 않는다.
- 기출 원문이 흐리거나 누락된 경우에만 자료 근거로 최소 보정하고 `확인 필요:`를 짧게 남긴다.
- 기출의 반복 개념과 문제화 방식은 추가 예상문제를 만들 때만 참고한다. 기출 원문 문제를 먼저 배치한 뒤 남는 핵심 범위만 추가 문제로 만든다.

1순위 수업자료 강조:
- PPT/PDF/슬라이드는 텍스트 추출만 믿지 말고 페이지 이미지를 직접 보면서 판단한다.
- 빨간색, 형광색, 굵게, 밑줄, 박스, 별표, 화살표, 도식 중심부, 비교표, 색상 구분, 반복 등장, 큰 글씨, 교수 강조 문구를 우선 문제화한다.
- 단순 디자인 테마 색과 실제 강조 색을 구분한다. 특정 개념에만 적용된 강한 색상은 중요하게 본다.

레퍼런스:
- 같은 과목의 이전 시험 정리자료나 레퍼런스 세트가 주변 폴더에 있는지 스스로 찾는다.
- 같은 과목 레퍼런스는 문제 깊이, 중요도 판단, 문제화 방식에 강하게 반영한다. 단, 경로 밖 레퍼런스는 참고만 하고 현재 문제의 정답 근거와 `출처:`로 쓰지 않는다.

이미지/표:
- 그림, 도식, 구조식처럼 문제를 풀기 위해 봐야 하는 자료만 문제 본문에 넣는다.
- 표, 비교표, 계산표, 빈칸표처럼 정답 판단 근거가 한눈에 드러나는 자료는 문제 본문에 넣지 말고 답안 아래 참고 이미지로 넣는다.
- 표가 외우기 어려우면 Markdown 표로 그대로 쓰지 말고 암기용 이미지로 재구성한다. 글자를 크게 하고 행/열 간격을 넓히고 핵심 칸을 색으로 강조한다.
- 시각 자료가 핵심인 문제에서 실제 캡처/크롭 이미지를 생략하지 않는다.

Markdown 형식:
```md
# 문제

실제 문제 텍스트를 바로 적는다.
![필요한 이미지](assets/과목명/img-001.png)

- 보기 A
- 보기 B

답: 보기 A
출처: 파일명.pdf p.12
```

작성 규칙:
- `# 문제`는 구분선일 뿐 제목이 아니다. 답을 유추하게 만드는 문제 제목을 만들지 않는다.
- 한 문제에는 문제 본문, 필요한 보기, 필요한 이미지, 답, 출처만 둔다.
- 모든 답안에는 반드시 `출처:` 줄을 둔다. 클릭 가능하도록 가능한 한 전체 파일 경로와 페이지/슬라이드 번호를 쓴다. 모르면 `출처: 확인 필요 - 파일명`.
- 답안은 줄글로 길게 쓰지 않는다. 자료에 있는 사실만 정답과 필요한 이유로 짧게 적는다.
- `암기포인트:`, `핵심:`, `요약:`처럼 자료에 없는 임의 라벨을 붙이지 않는다.
- 핵심 단어/숫자/조건/예외는 `**빨간 강조**`, 반드시 외울 묶음은 `==하이라이트==`로 표시한다. HTML 색상 문법은 쓰지 않는다.
- 단어, 짧은 구, 기호, 식, O/X, 키워드 나열처럼 문장이 아닌 답에는 마침표를 붙이지 않는다. 예: `답: O, 핵심 개념`.
- OCR이나 판독이 불확실하면 추측하지 말고 `확인 필요:`라고 표시한다.

최종 점검:
- 최종 Markdown과 assets가 지정 위치에 실제로 있는가?
- 기출이 있는데 기출 분석 없이 만든 문제가 없는가?
- 각 문제 답안에 `출처:`가 있는가?
- 그림/표/도식/색상 강조가 핵심인 문제에 실제 이미지가 들어갔는가?
- 문제 제목, 보기 순서, 단순 번호 순서만 보고 답이 유추되지 않는가?
