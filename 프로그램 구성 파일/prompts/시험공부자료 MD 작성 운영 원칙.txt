# 시험공부자료 MD 작성 운영 원칙

이 문서는 `AGENTS.md`가 참조하는 실전 운영 규칙이다. 기존 상세 프롬프트, 실패사례, 품질 규정집을 대체하지 않고 보완한다.

## 1. 출제 가능성 판단

- 문제 수를 미리 정하지 않는다. 실제 시험에 나올 가능성이 높은 것만 만든다.
- 가장 우선할 자료는 기출, 복원 문제, 교수님이 답까지 적어 준 페이지, 반복 강조된 페이지이다.
- 단, 현재 시험이 아닌 이전 시험 기출이 수업자료 안에 섞여 있는 경우에는 그대로 문제로 만들지 않는다. 문제 형식, 난이도, 교수님이 묻는 깊이만 참고하고, 현재 시험 문제는 기말 범위의 실제 내용에서 만든다.
- 수업자료에서는 빨간색, 형광색, 굵게, 밑줄, 박스, 별표, 화살표, 비교표, 도식 중심부, 반복 등장, 큰 글씨를 우선 본다.
- 지엽적인 단어보다 교수님이 짧은 서술형으로 물을 만한 중심 원리, 비교, 분류 기준, 설계 이유, 한계와 해결 전략을 우선한다.
- 과목의 시험 유형이 단답형/빈칸/짧은 서술형이면 억지 객관식을 만들지 않는다.

## 2. 해설 작성 원칙

- 해설은 답을 외우게 하는 보조 장치이다. 짧아야 할 때도 있지만, 이해가 필요하면 길어도 된다.
- 해설은 가능하면 `용어 정의 -> 전후 맥락 -> 왜 답이 되는지 -> 답안 작성 포인트` 순서로 쓴다.
- 직접 답안은 `답:` 바로 뒤에 짧게 쓰고, 전체 맥락·배경지식·용어 설명은 `[배경설명]` 또는 기존 호환용 `[해설]` 아래에 분리한다.
- "쉽게 설명"은 이상한 비유를 뜻하지 않는다. 먼저 용어와 관계를 정확히 정의하고, 그 다음 쉬운 말로 풀어 쓴다.
- 비유는 정말 도움이 될 때만 쓰고, 비유만으로 설명을 끝내지 않는다.
- 답안의 핵심 단어/숫자/조건/예외는 `**강조**` 또는 `==하이라이트==`로 표시할 수 있다.
- 해설은 출처 자료에 근거해야 한다. 출처에 없는 일반지식, 임의 암기법, 추측 해설을 넣지 않는다.

## 3. 객관식/OX 보기 처리

- 객관식 또는 OX 문제가 실제로 있을 때만 예방약학식 보기 리뷰를 적용한다.
- 문제 영역의 보기는 평범한 선택지로 둔다. 보기 안에 O/X, 정답 표시, 해설, 강조를 넣지 않는다.
- 답안 영역에서만 보기 리뷰를 한다. 가능하면 `[보기해설]` 섹션을 따로 두어 전체 배경설명과 보기별 설명이 섞이지 않게 한다.
- 맞은 보기는 필요할 경우 `O 원래 맞은 문장 // 왜 맞는지 쉬운 설명`으로 쓴다.
- 틀린 보기는 필요할 경우 `X 원래 틀린 문장 -> 맞게 고친 문장. 왜 틀렸는지 쉬운 설명`으로 쓴다.
- `->` 뒤에는 먼저 정정된 사실이나 정정된 매핑을 쓴다. 그 다음에 필요한 경우 한 문장 설명을 붙인다.
- 모든 보기에 해설을 억지로 붙이지 않는다. 함정, 짝짓기, 분류, 예외, 기전 비교처럼 헷갈릴 때만 붙인다.
- 공개 답안에서는 보통 O 항목을 먼저, X 항목을 나중에 묶어 보여 준다. 단, 문제 영역의 보기 문장 자체는 함부로 바꾸지 않는다.

## 4. 단답/짧은 서술형 처리

- 단답형 문제는 "키워드 하나"만 외우게 만들지 말고, 표현이 바뀌어도 답할 수 있게 개념의 정의와 이유를 같이 다룬다.
- 질문은 실제 시험처럼 물을 법한 형태로 쓴다: 정의, 비교, 분류 기준, 왜 그런지, 한계와 해결 전략, 실험 결과의 의미.
- 답은 직접 답안으로 쓸 수 있는 문장이어야 한다.
- 해설은 답보다 한 단계 쉬운 말로 전후사정을 설명하되, 자료에 없는 내용을 보태지 않는다.
- 약물명이나 고유명사는 사용자가 지정한 표기 규칙을 따른다. 별도 지시가 있으면 영어명 첫 글자 대문자처럼 통일한다.

## 5. 이미지와 출처

- 그림, 구조식, 표, 도식처럼 문제 풀이에 꼭 필요한 자료만 문제 본문에 넣는다.
- 표나 비교표가 답을 노출하면 문제용 이미지를 재구성하거나, 답이 보이지 않게 처리한다.
- 모든 문제의 답안 아래에는 `출처:`와 원본 출처 페이지 이미지를 둔다.
- `출처:`는 현재 시험범위 폴더 안의 파일만 사용한다.

## 6. 최종 점검

- `# 문제`, `답:`, `출처:` 개수가 맞는지 확인한다. 해설이 있는 세트라면 `[배경설명]`, `[보기해설]`, `[해설]` 섹션도 확인한다.
- 모든 이미지 링크가 실제 파일을 가리키는지 확인한다.
- 보기 줄에 `**...**`, `==...==`, O/X 표시, 원문 번호가 남아 있지 않은지 확인한다.
- 답안에 `ㄱ은`, `ㄴ은`, `답: ⑤`, `답: ㄱ, ㄴ`, `확인 필요`, `TODO`, ` / `가 남아 있지 않은지 확인한다.
- 기존 세트를 수정할 때는 사용자가 추가/삭제를 요청하지 않는 한 문제 수를 바꾸지 않는다.
