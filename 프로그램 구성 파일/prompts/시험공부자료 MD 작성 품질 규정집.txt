# 시험공부자료 MD 작성 품질 규정집

이 규정집은 새 문제 데이터셋을 만들거나 기존 문제셋을 수정할 때 항상 적용한다. 상세 프롬프트와 실패사례 문서보다 더 구체적인 금지 사례가 있으면 이 규정집을 우선한다.

## 1. 셔플 보기 독립성

- 앱은 `- 보기` 단위를 셔플한다. 따라서 각 보기는 단독으로 읽혀도 성립해야 한다.
- 보기 앞에는 `- ㄱ.`, `- ㄴ.`, `- A.`, `- ①`, `- 5.` 같은 라벨이나 번호를 붙이지 않는다.
- 조합형 보기(`① ㄱ, ㄴ`, `② ㄱ, ㄷ`)를 만들지 않는다. `옳은 것을 모두 고르시오`로 묻고, 정답은 실제 보기 내용을 줄 단위로 적는다.
- 답안에도 `답: ㄱ, ㄴ`, `답: ①`, `답: 5`처럼 라벨이나 번호만 쓰지 않는다.
- 답안/풀이에서도 `ㄴ은`, `ㄷ은`, `A는`, `2번은`처럼 보기 라벨을 참조하지 않는다. 틀린 이유도 실제 보기 내용으로 설명한다.

## 2. 보기 강조 금지

- 보기에는 `**...**` 또는 `==...==` 강조를 넣지 않는다.
- 보기는 정답 공개 전에 보이므로 강조된 보기만 보고 정답을 유추할 수 있다.
- 자료에서 강조된 핵심 단어라도 보기 안에서는 일반 텍스트로 쓰고, 필요한 강조는 답안에서만 사용한다.
- 표/이미지 문제도 문제 본문용 자료에는 빨간 숫자, 정답 표시, 채점 흔적, 답 암시 색상을 제거한다.

## 3. 답안 줄바꿈

- 여러 정답 보기나 풀이 문장을 ` / `로 한 줄에 이어 붙이지 않는다.
- 정답 보기, 틀린 이유, 비교 항목은 항목마다 줄바꿈한다.
- 공식, 비율, 짧은 키워드 묶음 내부의 `/`는 의미가 있을 때만 유지한다. 예: `체중 증가량 / 단백질 섭취량`, `n-6 / n-3`.
- `답:` 바로 뒤의 직접 답안은 자료에 있는 사실만 짧게 적는다. 긴 배경 설명은 `[배경설명]`, 보기별 설명은 `[보기해설]`로 분리하고, 임의 라벨은 만들지 않는다.

## 4. 문제 수 보존

- 기존 문제셋을 수정할 때 사용자가 문제 추가를 요청하지 않았다면 문제 수를 바꾸지 않는다.
- 특정 문항 수정은 해당 문항 안에서 처리한다. 새 `# 문제` 블록을 만들거나 기존 블록을 삭제하지 않는다.
- 수정 전후에 `# 문제`, `답:`, `출처:` 개수를 확인한다.
- 문제 수를 바꿔야 하는 경우에는 변경 이유와 최종 개수를 명시한다.

## 5. 최종 자체 점검

- 셔플되는 보기 안에 라벨, 번호, 강조가 없는가?
- 답안/풀이에 보기 라벨 참조가 남아 있지 않은가?
- 여러 정답/풀이 문장이 ` / `로 한 줄에 붙어 있지 않은가?
- 기존 문제셋 수정 시 문제 수가 의도와 다르게 변하지 않았는가?
- 각 문제에 `답:`과 `출처:`가 있고, 필요한 출처 이미지가 남아 있는가?
